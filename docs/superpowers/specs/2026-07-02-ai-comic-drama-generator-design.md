# AI Comic Drama Generator Design

## Overview

Build a single-user local Django web tool for creating AI comic drama content through OpenAI-compatible large model providers. Version 1 focuses on the core creative pipeline:

1. Generate multiple story outline candidates.
2. Let the user select one outline and ask AI to expand it into a script plan.
3. Generate storyboard prompts from the first complete episode script.

The project starts from an empty workspace. V1 intentionally avoids user accounts, permissions, multi-user collaboration, project history UI, and database persistence. Intermediate creative results are stored in local JSON files so the persistence layer can later be replaced with a database-backed repository.

## Product Scope

### In Scope

- Django-based web application.
- Server-rendered Django templates with light JavaScript for loading states and selection interactions.
- OpenAI-compatible model integration through `base_url`, `api_key`, and `model`.
- Model configuration through `.env`:
  - `LLM_BASE_URL`
  - `LLM_API_KEY`
  - `LLM_MODEL`
- Single-user local workflow.
- Local JSON workspace files.
- Fixed V1 creative constraints:
  - 60 episodes.
  - 2 minutes per episode.
  - 6 outline candidates per refresh.
  - Storyboard generation for episode 1 only.
- Genre dropdown with these initial options:
  - 逆袭爽文
  - 都市修真
  - 霸总甜宠
  - 重生复仇
  - 悬疑惊悚
  - 玄幻修仙

### Out of Scope

- Login and user management.
- Database-backed project storage.
- Multi-project history page.
- Full 60-episode complete script generation.
- Real-time streaming UI.
- Multi-provider settings UI.
- Image or video generation.
- Prompt marketplace or prompt versioning UI.

## User Workflow

### 1. Story Outline Page

The first page lets the user choose a genre from a dropdown. Episode count and duration are fixed at 60 episodes and 2 minutes per episode.

The page has a refresh button in the upper-right area. Clicking refresh calls the model and generates 6 outline candidates. Each candidate displays:

- Title.
- Core premise, randomly generated by the model.
- Protagonist.
- Hook or selling point.
- Broad 60-episode arc summary.

The generated candidates are saved to the current local JSON workspace file. The user selects one candidate and clicks `AI加工` to continue.

### 2. Script Processing Page

The second page receives the selected outline and calls the model to generate:

- A 60-episode script plan.
- A complete sample script for episode 1.

The 60-episode plan contains one structured item per episode. The complete episode 1 script is used as the source for storyboard prompt generation.

### 3. Storyboard Prompt Page

The third page generates storyboard prompts from episode 1 only. The result should contain about 12 to 20 shots for a 2-minute episode. Each shot contains:

- Shot number.
- Duration.
- Visual description.
- Character action.
- Dialogue or narration.
- Camera language.
- AI image prompt.
- AI video prompt.

## Recommended Implementation Approach

Use a Django single app, tentatively named `studio`, with server-rendered templates and a focused backend service layer.

This is preferred over a separate SPA frontend because V1 needs a reliable creative workflow more than complex frontend state management. The design still leaves room for a later React/Vue frontend because the business logic is kept in services and repositories rather than embedded in views.

## Backend Architecture

### Django Views

`views.py` handles HTTP requests, page rendering, redirects, and passing context to templates. Views must not directly build prompts, call provider APIs, or manually mutate JSON structures beyond orchestrating service calls.

Expected views:

- Outline page view.
- Generate outlines POST action.
- Select outline and continue action.
- Script page view.
- Generate script POST action.
- Storyboard page view.
- Generate storyboard POST action.

### LLM Provider

`llm/provider.py` provides an OpenAI-compatible client abstraction. It reads `.env`-backed settings and exposes methods such as:

- `generate_text(messages, temperature=None)`
- `generate_json(messages, temperature=None)`

The provider is responsible for:

- Validating model configuration.
- Calling the OpenAI-compatible chat completions endpoint.
- Returning raw text or parsed JSON.
- Raising explicit errors for missing configuration, API failure, timeout, and JSON parsing failure.

### Services

`services/outline.py` generates 6 structured outline candidates from a selected genre and fixed episode constraints.

`services/script.py` expands the selected outline into a 60-episode plan and a complete episode 1 script.

`services/storyboard.py` converts the episode 1 script into structured storyboard prompt entries.

Each service owns its prompt template and validates the shape of the model response before returning it.

### Repository

`repositories/workspace.py` owns local JSON workspace persistence. It should expose clear read/write/update operations and hide filesystem details from services and views.

The repository boundary is important because future database persistence should replace this layer without rewriting prompt services or views.

## Local Workspace Data Structure

Each local workspace file uses a structure like:

```json
{
  "id": "20260702-153000",
  "genre": "逆袭爽文",
  "episode_count": 60,
  "episode_duration_minutes": 2,
  "outlines": [],
  "selected_outline_id": null,
  "script_plan": [],
  "episode_1_script": "",
  "storyboard_prompts": [],
  "created_at": "",
  "updated_at": ""
}
```

### Outline Candidate

Each item in `outlines` contains:

- `id`
- `title`
- `core_premise`
- `protagonist`
- `hook`
- `arc_summary`

### Script Plan Episode

Each item in `script_plan` contains:

- `episode`
- `title`
- `summary`
- `key_conflict`
- `cliffhanger`

### Storyboard Prompt

Each item in `storyboard_prompts` contains:

- `shot_number`
- `duration`
- `visual_description`
- `character_action`
- `dialogue_or_narration`
- `camera_language`
- `image_prompt`
- `video_prompt`

## Page Interaction Rules

- Refreshing outlines regenerates and saves 6 outline candidates for the current genre.
- Selecting an outline saves `selected_outline_id`.
- Clicking `AI加工` navigates to the script page.
- Script generation saves `script_plan` and `episode_1_script`.
- Storyboard generation saves `storyboard_prompts`.
- Refreshing outlines should not erase an already generated script unless the user selects a new outline and generates a new script.
- Refreshing outlines clears the current outline selection for the new candidate set, while preserving previous script and storyboard fields as last successful results until they are overwritten by a new generation step.
- Each generation button needs a loading state to prevent duplicate submissions.

## Error Handling

- If `.env` model configuration is missing, the current page shows a clear model configuration error and does not call the provider.
- If the provider returns 401, quota errors, network failures, or timeouts, the current page shows a readable error and keeps the most recent successful result.
- If the model returns invalid JSON or misses required fields, the current page shows a response format error.
- Raw invalid model output should be preserved in debug logs to make prompt adjustments easier.
- A failed generation attempt must not overwrite the last successful workspace content.

## Testing Scope

V1 should include focused tests around the workflow boundaries:

- `LLMProvider` tests using mock responses:
  - Successful text response.
  - Successful JSON response.
  - API failure.
  - Invalid JSON.
- `JsonWorkspaceRepository` tests:
  - Create workspace file.
  - Read existing workspace file.
  - Update a subset of fields while preserving unrelated fields.
- Service tests:
  - Outline service builds the expected request and validates 6 candidates.
  - Script service validates 60 episode plan entries and episode 1 script.
  - Storyboard service validates 12 to 20 storyboard entries.
- Django view tests:
  - The three pages render.
  - POST actions write expected data into local JSON.
  - Errors are shown without deleting previous successful content.

Real provider end-to-end testing is manual for V1: configure `.env`, run the Django server, generate outlines, process one outline, and generate storyboard prompts.

## Future Extensions

- Add a project history page backed by the same workspace repository contract.
- Replace local JSON files with database models.
- Add a model settings page for multiple provider profiles.
- Add per-episode full script generation after the 60-episode plan is approved.
- Add editable prompt templates.
- Add image and video generation steps after storyboard prompts stabilize.
- Add export formats such as Markdown, JSON, CSV, or production sheets.
